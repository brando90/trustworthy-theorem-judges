# Does a gold reference help a theorem judge and bias its score?

**Doc link:** <https://github.com/brando90/trustworthy-theorem-judges/blob/main/docs/reference-anchoring-plan.md>

**TLDR:** Give a large language model (LLM) judge the same candidate theorem statements several times. Measure whether a randomly chosen gold reference improves its ability to distinguish covered from missed obligations, and whether it gives extra credit when the displayed reference happens to resemble the candidate. This is a proposed experiment. Its two predictions can succeed or fail independently.

## What must stay true when the reference changes?

VeriBench formal specification coverage (FSC) asks which required properties follow from a candidate's theorem statements. A candidate can cover a property with a stronger theorem or by combining lemmas. A reference can state a perfectly true theorem about a program and still ask for a different property. In that case a change in the judge's score can be correct.

Consider a function that sorts a list. Freeze two obligations: the output is sorted, and it preserves every element with its multiplicity. Reference A could express preservation as a permutation; reference B could express it as equality of counts for every element. A candidate written using counts should receive full credit under both references if it also guarantees sortedness. A candidate that promises sortedness alone misses preservation under both: a function returning the empty list on every input is a counterexample for nonempty inputs. Adding *stability* to B would change the target. This is an illustrative design, pending a checked Lean encoding.

## Make the comparison identifiable

1. **Freeze the target.** Start with the released `veribench@1.3` pack (896 tasks across six splits). Record the registry artifact digest, source, task identifiers, solver instruction version, candidate bytes and Lean toolchain. Keep previously rated file packets on their original snapshot. Record the mapping to release tasks and report the two populations separately. Stratify selection across benchmark splits and record eligible, excluded and unresolved tasks with reasons before looking at judge outputs.
2. **Build a reference pair.** For each task, two authors independently express the same fixed obligations in Lean. Preserve input domains, preconditions, edge cases, definitions, obligation weights and partial-credit boundaries. Prove both directions for each aligned obligation over an abstract implementation under the same assumptions. Splitting one theorem into two must preserve its weight. Check the proofs in Lean, audit axioms and run a no-candidate control for vacuity. Compiling two reference programs alone cannot certify equivalence. Keep pairs lacking a certificate in an exploratory human-adjudicated stratum.
3. **Freeze the candidates.** Include independently authored, fully covering candidates in A-like and B-like form, partial candidates missing a known obligation, and near-copy negatives with a consequential change. Label the form from construction or blinded review before scoring. Reserve literal self-copies for a positive control. Balance forms within task. Keep natural solver outputs as a separate deployment sample with frozen generator identities and sampling weights.
4. **Establish independent truth.** For each candidate and obligation, record covered, missed, or unresolved. A proof derives the target from candidate statements over an abstract implementation. A countermodel satisfies those statements and falsifies the target. Check domain consistency and rule out contradictory hypotheses. A proof timeout is unresolved. Use the existing packet builder for the original-reference rating round. Keep any alternate-reference packet independent and blind. Two Lean-literate raters independently score the same frozen file using the project's 0–5 whole-file rubric and record the obligation mapping. Blind them to model scores, candidate origin, arm names and each other's labels. Counterbalance reference presentation across raters; adjudicate disagreements after sealing the individual ratings. Preserve human and prover labels separately, including discordance.

## What the judge sees

For the controlled comparison, every call gets the same Python task, candidate statements, fixed neutral description of the required obligations, rubric, output schema and settings. The neutral description gives a reference-free judge an identifiable FSC target. Audit that it favors neither formalization. Return one covered/missed verdict per obligation and a separate 0–5 whole-file score. Keep the imports, definitions and signatures needed to interpret each reference in both proof conditions. Strip proof bodies, comments that reveal the arm, provenance and labels from the statements-only view. Render fresh independent calls in randomized blocks and hash the prompts outside the reference block.

| Arm | Additional material | What the comparison measures |
| --- | --- | --- |
| No formal reference | None | Baseline on the same coverage target |
| A or B, statements only | One certified reference | Average both arms with equal weight for reference utility. Use the within-candidate matching-minus-differing contrast for anchoring. |
| A or B, statements plus proofs | Exactly the same reference statements with their gold proofs | Does seeing a proof improve agreement or change anchoring? Hold candidate proof visibility fixed. |
| Both references | A and B identified as equivalent alternatives for the same obligations, in balanced order | Can multiple references recover credit while still rejecting near-copy negatives? |

Run the unmodified deployed scorer separately on its normal inputs and native scale, with exact backend, prompt, parser and aggregation pinned. Replay A and B through it. A literal source-and-candidate-only prompt is also informative, but it must infer the target; label that comparison as an effect of revealing the target as well as the reference. Do not use agreement from the controlled prompt as evidence about deployment without this replay.

## What counts as a reproduction?

| Question | Prespecified quantity | Decision |
| --- | --- | --- |
| Does the reference help discrimination? | Within each task compare judge scores for independently full and deficient candidates. Count a win as 1 and a tie as ½. Average across tasks, first averaging the A and B results (compare both candidates under the same reference), then under no formal reference. The difference is the change in task-averaged area under the receiver operating characteristic curve (AUC). | Positive gain with its paired 95% interval above zero. Also report absolute error against human scores. Better ranking alone establishes a discrimination gain. |
| Does a matching reference receive extra credit? | For each independently full candidate subtract its score under the differing equivalent reference from its score under the matching reference. Average within form, then equally across the two forms and across tasks. Report on the 0–5 scale. | Positive gap with its paired 95% interval above zero and specificity controls passing. Record whether it reaches the proposed practical threshold of 0.5 rubric points. |
| Does this cost valid answers credit? | Compare false rejection of full candidates under differing versus no formal reference and false acceptance of deficient candidates under uniformly assigned references versus none. Report numerators and denominators. | Freeze the pass cutoff against the human rubric on training data. Use identical thresholds across arms. A positive anchoring gap alone does not establish increased false rejection. |

Call the joint finding reproduced for a named judge only if the first two rows pass on the same held-out population. A discrimination gain alone supports reference utility. A matching advantage alone supports anchoring. If an interval spans zero and a meaningful effect, report inconclusive. A narrow interval that excludes the predeclared meaningful effect rules out an effect that large on this population. Estimate proof effects and proof-by-match interactions separately. For both-reference mitigation, require improved credit on differing valid answers and an upper confidence bound below a prespecified acceptable increase in false acceptance. Lock this tolerance on validation before testing.

## What would make us trust the result?

- **Controls.** An identical-reference repeat estimates scoring noise. Renaming binders should preserve scores. A third, independently valid candidate in neither reference's form supplies a signed A-versus-B placebo. Balance A/B identities and constrain the placebo interval to a prespecified equivalence band (proposed ±0.25 points). A stronger-but-different candidate deserves full credit. A vacuous candidate and a copied theorem with a stronger precondition or weaker conclusion that loses coverage should fail the relevant obligation; verify the loss with a witness. For a deliberate change of target, predict the score change from the altered obligation. Gold proofs can explain a target but cannot supply missing candidate coverage.
- **Human agreement.** Preserve each human score, inter-rater agreement and leave-one-rater-out agreement. Report judge and human means, judge-minus-human bias, mean absolute error, Spearman rank correlation and absolute-agreement and consistency intraclass correlations with their model and unit specified. Report score distributions and repeat variability. A constant predictor, theorem-count ratio, and lexical-overlap predictor expose easy shortcuts.
- **Judge selection.** Audit the exact rater and judge inputs with hashes. Read the untuned scores and rationales, require a label-in-prompt round trip, and fit two or three training examples as a pipeline check. Compare the existing deployed judge with a pinned open-weight judge. Tune one change at a time on training tasks, select any remedy on validation, and test the frozen configuration once. Treat previously inspected tasks as training or historical replication material. Keep task families, near-duplicates, both reference forms and all candidates for a task in one split. Hold an unseen solver family out for the deployment check.
- **Inference.** Aggregate three independent repeats within a cell using the frozen rule (mean for the controlled scores, median for the deployed scorer). Resample whole tasks, carrying every form, candidate, judge and repeat with each sampled task, for paired 95% intervals. Report each judge separately. Lock the primary judge and the joint claim before testing; label other contrasts secondary. Report the number of tasks with both classes, class and arm counts, floor/ceiling mass, unparsed scores and unresolved truth. Show worst/best-case bounds for missing outcomes and withhold a positive verdict if allowed completions reverse it.

## First run and decision to scale

1. **Start with one trace.** Take a non-vacuous public-release task with a small interface. Produce the two implication certificates, one full candidate of each form, one partial candidate and one near-copy negative. Verify the candidate and target hashes from the rater view through the score parser. Reject the construction if changing A to B changes any independent label or if its proof uses the concrete implementation to bypass the candidate statements.
2. **Pilot on six training tasks.** Aim for one eligible task per release split. Freeze the selection order, record failed attempts, and restrict the eventual claim if eligibility is narrow. With four candidates, three core arms, three repeats and two judges, the core pilot is 432 file-level requests, plus controls, proof arms and annotation. Log all excluded overhead separately and cap total calls, tokens, money and rater hours before dispatch. Estimate rater time from the trace. Small-sample effects are descriptive.
3. **Size and lock the test.** Use pilot task-level variance and eligibility to simulate the joint decision, targeting at least 80% power for a 0.5-point anchoring gap and a proposed 0.05 discrimination gain. Report required independent tasks, detectable effects and precision under the available budget. The values are design choices in rubric points and probability units. Freeze the release digest, task splits, judge versions, reference order, labels, missingness rules, controls, thresholds and analysis before unsealing test scores. If feasibility or power fails, publish the eligible pilot and bounds.
4. **Deliver the evidence.** Save the manifest, obligation mapping, Lean proof and countermodel receipts, blinded rating packets, versioned prompts, raw repeated outputs and parse status. Keep completed individual rating sheets private. Produce one main table with discrimination gain, anchoring gap, false rejection and false acceptance, plus a paired plot connecting each candidate's scores under A and B. Keep the proof comparison and natural solver replay in separate panels. Report eligibility and uncertainty alongside any recommendation to change the deployed judge.
