### Why Grok and Gemini are not native

VeriBench experiment 107 produced the Grok 4.7 and Gemini 4 Argon files through Vals' Valkyrie service, which runs Terminus 2 against its model gateway. The native agents (xAI's Grok CLI, Google's Antigravity) were not in Vals' agent registry, and Vals declined native third-party agents and raw provider keys (experiment 107, amendment 9 and its addenda). In this experiment, the planned Google run used the Pi harness with Gemini 3.8 Flash and returned 0 of 25 files. Native Grok and Gemini files would therefore be new generation runs, not a relabeling.

**Confounding note:** prompt versions (`5`, `8`, `7`) and harnesses (Codex, Claude Code, Terminus 2) differ across agents, so cross-agent differences from this round are confounded with prompt version and harness; the collection supports human-rating data and held-out judge evaluation. **Isolation flag:** `4` included files (`1` Grok 4.7, `3` Gemini 4 Argon) have receipts showing egress beyond the gateway was not blocked; they held no reference Lean or tests and made no network calls, and are flagged for a sensitivity analysis (VeriBench experiment 102, amendment C13). Item-to-model keys stay in git-ignored `sealed/` while raters score. **Blinding exposure:** public Git history shows which files each commit added (for example, the Gemini 4 Argon files in `7c4533f` and the 21 files completed in `26a9e67`), so a rater who browses this repository's history could identify some agents; rater emails no longer link to the repository, and the analysis should record this possible exposure.
