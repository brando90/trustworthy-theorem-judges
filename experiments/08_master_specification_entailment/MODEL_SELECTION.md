# Experiment 08 open-weight route selection

On 11-08-2026, the route survey selected locally cached `Qwen/Qwen3.6-27B`, revision `6a9e13bd6fc8f0983b9b99948120bc37f49c13e9`, in unquantized bfloat16 on one empty NVIDIA B200. All 15 weight shards were independently SHA256 verified. The server loaded the exact snapshot and returned healthy status plus matching model metadata. The route worker made zero generation calls and incurred $0 provider charges.

The choice is a credible strong general reasoning/instruction model within the fixed hardware and time budget; it is not established best for semantic entailment judging. Complete local alternatives included Qwen3-Coder-30B-A3B-Instruct, Goedel-Prover-V2-8B, DeepSeek-Prover-V2-7B and Phi-4. Goedel-Prover-V2-32B had metadata only. Existing Brando-owned mercury1 Qwen3-14B and 4-bit Qwen3-32B-AWQ servers were inspected via metadata requests and left untouched. Mercury1 had only two empty 16 GB devices, insufficient for the selected BF16 model. Mercury2 and skampere1/2 remain unobserved because fresh-connection spacing constrained the initial survey; the coordinator stopped optional further survey after establishing this ready route. No cross-host global-optimum claim is supported.

The [official model card](https://huggingface.co/Qwen/Qwen3.6-27B), accessed 11-08-2026, supports direct-response mode with `chat_template_kwargs: {enable_thinking: false}`; that branch was verified in the cached tokenizer without generation. This mode is bounded direct response, not maximum-reasoning capability. General mathematics/coding results in the card do not validate probability judging on these controls. The [Goedel primary card](https://huggingface.co/Goedel-LM/Goedel-Prover-V2-8B) concerns formal proof generation, and the [Coder primary card](https://huggingface.co/Qwen/Qwen3-Coder-30B-A3B-Instruct) concerns coding capabilities.

Pinned stack: vLLM 0.17.1, PyTorch 2.10.0+cu128, Transformers 4.57.6, Python 3.12.13. The model card recommends vLLM>=0.19.0; this installed 0.17.1 version includes the required architecture and successfully loaded the model. That version difference is explicit. Dedicated settings are tensor-parallel 1, context 8192, max sequences 1, GPU memory fraction 0.65, eager execution, seed 11082026, qwen3 reasoning parser, language-model-only, no tools/speculation/fallback. The experiment owner separately freezes sampling, prompt, timeout and call accounting.

Two pre-generation setup issues were preserved: an initial nonpersistent launch ended before logging, and vLLM 0.17.1 rejected UUID-form CUDA visibility. A verified numeric device index and a persistent session resolved them. No measured cell was rerun. All detailed model hashes and sanitized candidate availability are in the companion JSON records.
