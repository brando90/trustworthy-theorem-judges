\subsection*{Bottom line}
Choosing the judge by validation loss (\F{3}) did not beat fitting by loss on all 20 training tasks (\F{4}) on held-out tasks.
\F{3} by validation RPS is worse on RPS than \F{4} (paired difference $+0.0210$, 95\% task-bootstrap interval $[+0.0144, +0.0280]$,
above zero), and \F{3} by validation CE collapses to the constant forecast (picked in 996 of 1,000 splits).
\F{2} (Pearson-trained mixture) and \F{4} (CE-trained mixture) still tie on RPS ($-0.0056$ $[-0.0181, +0.0059]$ for \F{4} minus \F{2}).
Retrospective: cached judges, 25 tasks, 75 artifacts, no model calls, \$0.

\subsection*{Caveats}
\begin{itemize}
  \item Five test and five validation tasks per split is tiny; the 1,000 splits reuse the same 25 tasks, so the intervals come from the task bootstrap only and the true uncertainty is wider than the number of splits suggests.
  \item The candidate family is small (five cached judges, mixtures); no new prompts, no agent search, so this does not test \F{3} as a prompt or model search. The cached judges' prompts were developed with the original train split, so held-out tasks may have been seen at design time.
  \item Why \F{3} loses (a noisy ranking of near-identical candidates) is a reading, not tested. Validation CE is dominated by near-zero probabilities, so \F{3} by CE returns the constant almost always.
\end{itemize}
