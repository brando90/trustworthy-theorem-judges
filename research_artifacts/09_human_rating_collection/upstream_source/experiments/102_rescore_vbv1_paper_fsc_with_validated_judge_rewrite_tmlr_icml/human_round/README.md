## Why a new round, and why only evaluation

- **The old ratings are used up.** All 75 existing ratings have been seen: training wrote experiment 100's conventions and supplies its rated examples, validation chose the judge, the test was read once, and later audits read every item's error. None can become unseen again.
- **The judge needs few labels to build**, so new ratings go entirely to evaluation.
- **Three gaps are open:**
  1. The validated judge's ordinary-item test agreement rests on 8 tasks, with a Spearman interval that crosses zero (0.652 [−0.17, 0.92]).
  2. It was validated on outputs of one older model, `claude-3-7-sonnet-20250219` (three temperature-0.7 samples per task, generated by January 2026 and rated in late April and early May 2026), not on frontier-agent outputs.
  3. It is lenient in the partial-coverage band: experts' 0.44 becomes about 0.78.

  This round measures agreement on current frontier outputs, and the experts' own absolute level of coverage.

## The design (protocol § C)

### Sample (C1)

- **Tasks:** 25 VeriBench V1 (VBV1) tasks, 5 from each of the five splits outside IndustrySet: easy, cs, humaneval, realcode, security.
- **Exclusions:** tasks in experiment 100's 25-task pool, and any task whose reference has a vacuous `def Post ... := True` placeholder.
- **Stratification:** within each split, tasks are stratified by the Tier-1 validated FSC (formal specification coverage) of the Claude Code candidate.
- **Candidates per task:** Claude Code, Codex, and alternately Leanstral or the single-call baseline. That gives 75 items, spanning poor to strong.
- **Seed:** 20260929.

**How [`../scripts/draw_human_round_sample.py`](../scripts/draw_human_round_sample.py) implements C1.** These choices were fixed on 09-29-2026, before any Tier-1 score exists:

1. **Eligible task.** A task from the five splits outside IndustrySet is eligible when all of the following hold:
   - both the Claude Code and the Codex candidates were judged, meaning both judge members made at least one COMPLETE call (the missing-member rule in `results/LOCK.json`);
   - at least one of the Leanstral and baseline candidates was judged in the same way;
   - its reference has no placeholder;
   - it is not in the existing pool.

   Empty outputs are never rated: they score 0 without a judge call, and every rater would agree on them trivially.
2. **The existing pool is matched by file path**, using experiment 100's `inputs/provenance.json`. Its labels differ from the current file names for four realcode tasks (for example, the label `1_bisect_left` is the file `2_bisect_left`).
3. **Also excluded: the pool's security siblings.** These are the five vulnerable variants of the five security pool tasks (for example `vulnerabilities/0_unsafeCopy` for `safe/0_unsafeCopy_safe`). Each is the same program with the safety fix removed. The raters already rated the safe versions, and experiment 100's audits studied them item by item, so excluding the variants keeps every sampled program new to both. This is stricter than the literal protocol text; `--no-sibling-exclusion` reproduces the literal rule.
4. **Placeholder check.** Any postcondition definition (`Post`, `Post_prop`, `PostCond`, any binders) whose whole body is `True` excludes the task. The check runs on two references:
   - the reference the judge saw, which is the frozen 09-02-2026 snapshot bound in `LOCK.json`;
   - the released reference at the checkout's `HEAD`.

   On experiment 100's rating-era files, the detector flags exactly its five placeholder references and nothing else; it flags none of the 896 current references.
5. **Strata.**
   - Within a split, the eligible tasks are ranked by the Claude Code score, with ties broken by the seeded stream.
   - The ranked list is cut into five equal-count groups, and one task is drawn uniformly from each group.
   - Equal-count groups keep each split's sample proportional to that split's own score distribution: every fifth of the distribution is represented, and extreme scores are not oversampled.
   - Splits are equally represented (5 tasks each), unlike the population (security has about 450 eligible tasks, cs about 20), so population estimates are reweighted (see C6).
6. **Alternating third candidate.**
   - The 25 slots run in a fixed order: easy, cs, humaneval, realcode, security, and strata 1 to 5 within each split. The plan alternates Leanstral, baseline, Leanstral, and so on, giving 13 Leanstral and 12 baseline items.
   - If a slot's planned system has no judged candidate in its stratum, the slot takes the other system, and a later slot repays it. This keeps 13/12 whenever the data allow.
   - Only 210 of the 614 baseline outputs (tasks outside IndustrySet) are non-empty. Outside the pool, 3 are in cs and 2 in realcode, so expect fallbacks there, repaid in security (175 available). The sealed key records every slot's planned and assigned system.
7. **Blinding order.** Folder numbers R01–R25 and the letters a–c within a folder are random permutations from the same seeded stream. The order in which the stream is consumed is fixed in the script.
8. **Frozen inputs only.** The script refuses to draw in any of these cases:
   - the Tier-1 items file's SHA-256 differs from `LOCK.json`;
   - any Tier-1 cell still lacks its receipts;
   - a judge-seen file cannot be read and verified on the host;
   - the seed is not 20260929.

   It draws once: it refuses to overwrite an existing manifest, and `--verify` re-derives the draw and compares fingerprints.

### Timing

The sample is drawn **after Tier 1 finishes and before any rater sees anything**. The script cannot run earlier: it refuses while any Tier-1 cell lacks receipts.

### What raters see (C2)

- **The original rater instructions, verbatim.** These are [`py_src/veribench_prompts/human_judgements_prompt.md`](../../../py_src/veribench_prompts/human_judgements_prompt.md), SHA-256 `b29e9caf…`, byte-identical since 05-04-2026. It is the file behind `rater_instructions()` in experiment 100's `scripts/prompts.py`, and the packet carries a byte copy. [`RATER_INSTRUCTIONS.md`](RATER_INSTRUCTIONS.md) only explains the packet and the sheet; it does not restate the rubric.
- **The files, exactly as the judge saw them.** Per task: the Python source, the reference and three candidates, with the bytes the judge saw in Tier 1 (the Python block the solver saw, the frozen reference, the frozen candidate). They are pinned by SHA-256 in the packet's `FILES.sha256` and in `SAMPLE_MANIFEST.json`.
- **Hidden:** system names, judge scores and strata. Only the sealed key `sample/sealed/UNBLINDING_KEY.json` holds them.
  - The key's SHA-256 is in the manifest, which is committed before anyone rates.
  - The key itself is committed only after every sheet is in; `.gitignore` keeps it out until then.
- **Identity hints.** Candidate files that mention a model or vendor name are flagged in the key but not edited, because raters must see the judge's bytes. The analysis discloses them.

### Raters (C3)

- **Who:** at least two experts, ideally original participants 1–3, each rating independently in their own sheet. The expert list is fixed when raters are recruited and passed to the analysis as `--experts`; other raters' sheets are reported separately.
- **Who contacts them:** Brando. This package includes a [draft email](rater_email_DRAFT.md), which has not been sent.
- **Workload (an estimate from file sizes, not a measured time):**
  - Median lines per file in the frozen outputs: Claude Code 211 (90th percentile 396), Codex 124, Leanstral 70, non-empty baseline files 78.
  - References have a median of 200–680 lines by split, and the Python 33–117.
  - At roughly 20–40 minutes per task, this is about 8–17 hours per rater.

- **Target.** The mean of the available expert final scores, divided by 5. Missing ratings are omitted, never zero-filled, as in experiment 100.
- **Primary (C5).** Agreement of H2 with the expert mean on ordinary items, which here means all 75, since placeholders are excluded by design:
  - Spearman with a 95% task-bootstrap interval (10,000 draws, seed 20260929);
  - Kendall τ-b, Pearson, ICC(A,1) and ICC(C,1) (intraclass correlation, absolute-agreement and consistency forms);
  - MAE (mean absolute error), raw and mapped through protocol B's `apply_mapping`;
  - repeat SD, the per-pass mean of the two members as in experiment 100's `ensemble.py`.
- **C5 gates (all must hold):**
  - Spearman ≥ 0.45, and its bootstrap lower bound > 0.20;
  - ICC(A,1) ≥ 0.40;
  - mean repeat SD ≤ 0.10.

  The verdict is PASS, FAIL, or NOT_EVALUABLE (fewer than two expert sheets, or a missing statistic). Experiment 100's extra test-receipt check (90th-percentile repeat SD ≤ 0.20) is reported beside the verdict but is not part of the C5 gate.
- **Pooled held-out estimate.** Experiment 100's 10 test tasks, rebuilt from its committed receipts and checked to reproduce its test receipt exactly, plus the 25 new tasks. It is reported for all 35 tasks and for the 33 ordinary ones. The pool mixes 2026-05 candidates rated by the first-round experts with frontier candidates rated in this round; that difference is disclosed wherever the pooled number appears.
- **Secondary (C6):**
  - expert-rated FSC per system, with task-bootstrap intervals;
  - for Claude Code and Codex, a design-weighted estimate for the eligible population, which weights splits by pool size and resamples tasks within splits;
  - the protocol § D2 reading (≤ 0.50 unsaturated, ≥ 0.80 saturated) of the best frontier row on the experts' scale;
  - the mapping's transfer test: MAE and bias, raw against mapped, compared with its experiment-100 test values.
- **Descriptive, never used for a decision:**
  - human leave-one-expert-out agreement, with the judge scored on the same targets (the like-for-like comparison from experiment 100's audit, finding 5);
  - agreement among the experts;
  - the deployed judge against the experts;
  - spam-free base scores, for audit finding 3.
- **Implementation.** Statistics come from experiment 100's [`scripts/metrics.py`](../../100_karpathy_recipe_tc_judge_search_human_train_val_test/scripts/metrics.py), imported unchanged from its path; its SHA-256 is recorded in every output.

## How to run it

1. **Now (done):** these files. `draw_human_round_sample.py --dry-run` and `analyze_human_round.py --synthetic-selftest` run the full code on synthetic data written to a temporary directory outside the repository.
2. **After Tier 1 finishes,** on skampere1 in the experiment-102 checkout, run `python3 scripts/draw_human_round_sample.py`.
   - It uses `LOCK.json`'s items file and the runs `t1_H2_sol_high` and `t1_H2_opus55_max`, and writes `human_round/sample/`.
   - Commit `sample/SAMPLE_MANIFEST.json` and `sample/packet/`; leave `sample/sealed/` uncommitted.
3. **Optional secondary judge:** run experiment 104's final judge on the 75 items, and commit its predictions before the packet is sent.
4. **Brando** sends the packet (a zip of `sample/packet/`) with the email, always with a working Google Drive link in the body, because Stanford mail strips `.zip` attachments (rule and evidence: `PLAN_setN_rating_round.md`, "Delivery links required", 10-20-2026).
5. **Collect the sheets** as `human_round/ratings_setB/<rater_id>.csv` for set B (the primary set, C9), `human_round/ratings/<rater_id>.csv` for set A, and any optional extension sheets as `human_round/ratings_extension/<rater_id>.csv`, and commit them. Then commit every key with `git add -f human_round/sample_setB/sealed/UNBLINDING_KEY.json human_round/sample/sealed/UNBLINDING_KEY.json human_round/sample_extension/sealed/EXTENSION_KEY.json`; they are ignored until then.
6. **Analyze:** run `python3 scripts/analyze_human_round.py --experts <rater ids>`. Once `sample_setB/SAMPLE_MANIFEST.json` exists, set B is the primary set and set A the secondary set (C9); each set with sheets gets `human_round/analysis/ANALYSIS_set{B,A}.{json,md}`, and the primary set is also written as `ANALYSIS.{json,md}`. Every set reports C5, C6, C7's per-system tables (set A also with the extension's sheets) and C8: the experts' own coverage per system with the D2 reading, within- and between-task agreement, the frontier sign agreement, rater severity, and every primary statistic again with the author's sheet (`--author`, default `A1`, never in the primary target). Report the result in `../results.md`, and record any deviation in `../REPORT.md`.

## Integrity rules

- **Only people rate.** Never fabricate a rating, and never let a model stand in for a rater. Synthetic data exist only inside the dry run and the self-test, are generated at run time and written outside the repository, and are never committed as results.
- **One draw, one analysis.**
  - There are no redraws.
  - The analysis, gates, expert list and secondary judge are fixed before any rating arrives.
  - Deviations go to `../REPORT.md` with a timestamp and reason.
- **Nothing outward-facing without Brando.** No email, upload or post is made by an agent.

TL;DR: Protocol C is ready to run but blocked on Tier 1. Once Tier-1 scores exist, one command draws 25 tasks × 3 blinded candidates (75 items) and freezes the H2 scores in a sealed key. Brando then sends the packet to at least two experts. When their sheets are in, a locked script reports H2's agreement on fresh frontier outputs against the C5 gates, plus the experts' own coverage level for each system.
